      3 bmqsim is part of BondMachine project. It is a library and a CLI tool to produce HDL code and test benches to simulate a quantum computer on FPGA using the BondMachine architecture framework. It also provides a sotfware simulator to be used in a CPU.
      4 The installation of bmqsim is part of the standard installation of BondMachine framework. Please refer to the [BondMachine quick start](http://bondmachine.fisica.unipg.it/docs/#quickstart) for the instructions.
      5 
      6 ## Usage
      7 
      8 To use the bmqsim CLI tool, you have to choose two things: the backend and the quantum algorithm to simulate.
      9 The backend creates target hardware architecture of a specific type and its flavor (the subtype as for example the `only real numbers` or the `complex numbers` flavor) if applicable.
     10 The quantum algorithm is a file containing the quantum circuit to simulate. Let's begin the latter.
     11 
     12 ## Quantum algorithm
     13 
     14 The quantum circuit is a file containing the quantum algorithm to simulate. The file is written in the the same format as the one used by the Basm assembler and has the bmq extension. The file is a sequence of instructions, each one in a line inserted in a **block** section. To instruct the simulator, outside the block section, you can use the `%meta` directive to specify the simulator metadata.
     15 
     16 The following is an example (*program.bmq*) of a quantum algorithm file implementing the Bell state:
     17 ```bmq
     18 %block code1 .sequential
     19 	qbits	q0,q1
     20 	zero	q0,q1
     21 	h	q0
     22 	cx	q0,q1
     23 %endblock
     24 
     25 %meta bmdef global main:code1
     26 ```
     27 ## Backend
     28 
     29 Once you have the quantum algorithm, you can choose the backend to use. The backend creates the target hardware architecture of a specific type and flavor. 
     30 The subsequent tables show the available backend and architectures types, their flavors and the relevant command line options:
     31 
     32 | Architecture type (backend) | Command line option | Description | Flavors | 
     33 | --- | --- | --- | --- |
     34 | `Software` | `--software-simulation` | Software simulator | `None` |
     35 | `MatrixSeqHardcoded` | `--build-matrix-seq-hardcoded` | Sequence of matrices hardcoded in the FPGA | `seq_hardcoded_real`, `seq_hardcoded_complex` |
     36 | `MatrixSeq` | `--build-matrix-seq` | Sequence of matrices in the FPGA | *Not yet implemented* |
     37 | `FullHardwareHardcoded` | `--build-full-hardware-hardcoded` | Full hardware with hardcoded matrices | *Not yet implemented* |
     38 
     39 Each architecture type is associated to a different set of command line options and activates a different simulator backend. Some of the options are common to all the backends, while others are specific to a single backend. The following sections describe the possible backends and the options.
     40 
     41 ### Common options
     42 
     43 | Option | Description |
     44 | --- | --- |
     45 | `-hw-flavor-list` | List the available flavors for the chosen hardware architecture. |
     46 | `-hw-flavor` | Choose the flavor of the hardware architecture. |
     47 | `-save-basm` | Save the BondMachine Assembly code for the Basm assembler. |
     48 | `-build-app` | Build the application template to use the selected hardware architecture. |
     49 | `-app-flavor-list` | List the available flavors for the chosen application template. |
     50 | `-app-flavor` | Choose the flavor of the application template. |
     51 | `-app-file` | Choose the file name of the application template. |
     52 
     53 ### Software simulator
     54 
     55 The software simulator backend is used to simulate the quantum algorithm on a CPU. The program accept a json input file and produces a json output file.
     56 The following table shows the command line options specific to the software simulator:
     57 
     58 | Option | Description |
     59 | --- | --- |
     60 | `-software-simulation-input` | Choose the input file for the software simulator. |
     61 | `-software-simulation-output` | Choose the output file for the software simulator. |
     62 
     63 An example of usage of the software simulator with the Bell state algorithm previously described (*program.bmq*) is the following:
     64 ```bash
     65 bmqsim --software-simulation --software-simulation-input input.json --software-simulation-output output.json program.bmq
     66 ```
     67 where `input.json`, the input file for the software simulator, is:
     68 ```json
     69 {
     70 	{"Vector":[{"Real":1,"Imag":0},{"Real":0,"Imag":0},{"Real":0,"Imag":0},{"Real":0,"Imag":0}]}
     71 }
     72 ```
     73 and `output.json`, the output file produced by the simulator, is:
     74 ```json
     75 {
     76 	{"Vector":[{"Real":0.7071067,"Imag":0},{"Real":0,"Imag":0},{"Real":0,"Imag":0},{"Real":0.7071067,"Imag":0}]}
     77 }
     78 ```
