      1 ## __Instructions__ ##
      2 
      3 Basm instructions are identified by an operation that requires operands to be processed. Operands can be registers, memory address or more generally any SOs I/O ports.
      4 Some instructions do not require an operand, whereas some other instructions may require one, two, or three operands.
      5 
      6 The first operand is generally the destination and the second operand is the source.
      7 
      8 ## Pseudo instructions ##
      9 
     10 Pseudo instructions are not real instructions, they are directives that are translated into one or more real instructions. They are used in the instruction field anyway because that’s the most convenient place to put them. The most common pseudo instructions are the ones that define data and reserve storage space. They are used to define constants and variables and to reserve space for arrays and other data structures.
     11 
     12 ### Declaring data ###
     13 
     14 The declaration of data is done in data sections by using the syntax:
     15 
     16     symbol directive expression [, expression]...
     17 
     18 **symbol** is the name of the variable. It can be any valid identifier. It as to be unique in the current section.
     19 
     20 **directive** is the name of the directive that declares the data. The list of directives is given in the table below.
     21 
     22  **expression** is a constant expression that evaluates to a byte (or other types according to the directives) value. The assembler assigns the first expression to the first byte of the variable, the second expression to the second byte, and so on. The assembler automatically advances the location counter by the number of bytes declared.
     23 
     24 The following table lists the directives that can be used to declare data:
     25 
     26 | Directive     | Type | Description  | Example |
     27 | -------------:|:-------------|--|--|
     28 | db            | Initiatialized data | Declare byte | examplevar db 1, 2, 3 |

     32 ## Expressing I/O ##
     33 
     34 Apart from operations among internal elements, CP instructions can interact with external objects. These can be memories, like in standard processor, or more generally can be all kind of SOs. Basm has a special syntax to express such data movements. The most common instruction is _**mov**_ and  the general syntax for the I/O objects is:
     35 
     36     [IO object name][object index]:[I/O port]
     37 
     38 If the object has no port the colon can be omitted. Similarly, if the object has no index, just the name can be used alone.
     39 
     40 Following is a list of examples of I/O objects:
     41 
     42 | Object name        | Description  |
     43 | :-------------| :-----|
     44 | *ram* | The random access memory |
     45 | *rom* | The read only memory |
     46 | *i* | The input |
     47 | *o* | The output |
     48 | *vtm* | The video textual memory |
     49 | *q* | The shared queue |
     50 | *s* | The shared stack |
     51 
     52 The I/O port can be addressed in two ways:
     53 
     54 - *Immediate addressing*: An immediate port has a constant value or an expression.
     55 
     56 - *Register addressing*: In this addressing mode, a register contains the port. In this mode the register name is surrounded by brackets.
     57 
     58 - *Symbol addressing*: In this addressing mode, a symbol refers to a port. 
     59 
     60 
     61 Here is some examples along with theirs descriptions:
     62 
     63 | Example        | Description  |
     64 | :-------------| :-----|
     65 | *mov r0 5* | The register _**r0**_ is filled with the decimal value of 5|
     66 | *mov r1 i0* or *mov r1 i0:*| The register _**r0**_ is filled with the value read from the input _**i0**_
     67 | *mov vtm0:48 r0* | Copy the value contained in the _**r0**_ register into the location 48 of the video textual memory using immediate addressing |
     68 | *mov vtm0:[r1] r0* | Copy the value contained in the _**r0**_ register into the location of the video textual memory pointed by the _**r1**_ register using register addressing |
